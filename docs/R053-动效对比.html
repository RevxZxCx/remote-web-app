动效缓动：平台默认 vs 设计稿基准

同样是 240ms 的淡入，两条曲线的差别在「前 1/4 时间里走了多少」——不是时长问题，是节奏问题。

一、两条曲线差在哪

设计稿基准 应统一到这条
cubic-bezier(.2, 0, 0, 1) · Motion.Emphasized
起步就快，接近终点时明显减速——「被推出去然后停住」。
平台默认 69 处实际在用它
FastOutSlowInEasing(0.4, 0, 0.2, 1)
两头都慢、中间急。标准 ease-in-out，和设计稿不是同一种手感。
对角线 = 匀速
linear
只作参照。两条曲线都在它上方 = 都是「先快后慢」。

五、诚实评估：值不值得做

会改善什么
· 消息淡入、面板展开起步更利落，不再有「愣一下」
· 全 App 动画节奏真正统一到一套刻度
· 设计稿的对齐从「写了但没用」变成真的落地
· 顺带修 5 处连时长都不对的 AV
风险与代价
· 65 处分散在多个屏，纯手工核对，量大
· 没有测试能守「曲线对不对」——视觉属性，Robolectric 量不出
· 不是「一眼看出 bug」的改动，收益偏主观
· 需要全量回归保 1596 条不掉
一句话：不改不会有任何功能故障；改了是「整体手感从『还行』到『利落』」。 这是一次纯打磨，不是修 bug。
