4规则与边界


  

    

      规则来源说明
    

    

      卡片最多 3 个按钮
      实测
      加到第 4 个直接被系统吞掉，不报错、不换行。所以多选题超过 3 项的，卡片只放
        选项A / 选项B / 更多，详细选项回 App 里选。
    

    

      必须 ongoing
      官方
      setOngoing(true)。这也是为什么它天然适合「正在执行」而不适合「收到一条消息」。
    

    

      不能自定义布局
      官方
      不支持 customContentView。卡片的排版由系统决定，我们只能填标题/副标题/进度/按钮。
    

    

      渠道不能是 IMPORTANCE_MIN
      官方
      项目现有 SERVICE 频道正是 MIN，且频道建好后不可改重要性——必须新建频道。
    

    

      不合并前台服务通知
      设计
      两条通知职责不同：SERVICE(MIN) 只为满足前台服务硬要求；流体云只管任务进度。
        合并会让用户切到任何 App 时状态栏都挂着胶囊，很快被反感后一关就永久失效。
    

    

      不用于「聊天消息」
      合规
      官方明确把聊天消息列为不适用场景。我们只用它表示进行中的工具执行 / 等待用户输入，
        不用来提示「助手回了新消息」。
    

    

      默认关闭
      实测
      AppOp 默认 ignore，且零售机上 pm grant / cmd appops set
        会被 SecurityException 拒绝——只能引导用户手点，无法程序代劳。
    

  


  

    降级路径：canPostPromotedNotifications() 为 false（用户没开、或系统低于
    Android 16）时，所有状态照常走现有普通通知，功能一个都不少，只是没有状态栏胶囊。
    这意味着这部分实现不会让老设备变差。
  






  
5待你拍板的三件事

  

    
问题我的建议

    

      胶囊常驻到什么时候？
      建议：任务结束立即消失；出错保留到用户点掉。不要「连接着就一直挂」。
    

    

      批复类要不要在卡片上直接做？
      建议：批准/拒绝提供「只批这一次」的按钮；带「记住」的选项一律回 App 里，避免误点。
    

    

      回答类做几个选项？
      建议：卡片只放前 2 个 + 「更多」。选项超过 3 个时，卡片上文字会挤成省略号，体验反而差。
