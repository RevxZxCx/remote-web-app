把 T076 的「右滑开洞察」换成两半各管一个方向：左半屏右滑 = 最近会话抽屉，右半屏左滑 = 总上下文洞察抽屉。

1为什么现在的手感是错的

T076 交付的手势规则是「起点在左缘 24dp 内 → 会话抽屉；其余区域右滑 → 洞察」。这条规则有两个问题：
① 方向反了：洞察抽屉在右边，却要求向右滑才能拉出来 —— 手指往右走、面板从右边出来，两者是逆着的。真机上会明显觉得「要往反方向推」。
② 两个抽屉抢同一个方向：会话抽屉在左、也要向右滑，于是只能靠 24dp 的窄带子区分。那条带子只有 9mm 宽，十次里有几次划不准，用户根本没法形成肌肉记忆。

改成按半屏分区、并且方向和抽屉所在侧一致之后：左边的东西从左拉、右边的东西从右拉，两个手势的方向互不相同，不再需要一条 24dp 的窄带来仲裁。

分区怎么画（图解）：
屏幕沿垂直中线对半分，中线两侧各归一个抽屉。

左半屏 · 向右滑 → 最近会话抽屉
抽屉本来就在左边，向右滑是把它从左侧拉出来，方向和物体的位置一致。

右半屏 · 向左滑 → 总上下文洞察抽屉
抽屉本来就在右边，向左滑是把它从右侧拉出来，同样一致。

为什么这样就好用了：两个手势的方向相反，手指往哪边走，就从哪边出东西。不再有「两个抽屉抢同一个右滑、只能靠 24dp 窄带仲裁」的问题 —— 那条窄带是 T076 里唯一需要用户「瞄准」的东西，也是最难形成肌肉记忆的地方，现在整条规则里没有它了。

24dp 还需要吗：不再需要。分区边界是中线的一半屏宽（360dp 屏上是 180dp），容错面积是原来的 7.5 倍。

2四类手势：两类已定，两类要你拍板

已定的两类直接对应你说的那句话，没有歧义。剩下两类是方向与所在半屏相反的手势 —— 比如「在右半屏继续向右滑」，它既不是「拉出左边的会话」，也不是「拉出右边的洞察」。这两类现在必须给一个明确结果，否则会出现「划了没反应，但列表被拖歪一下」的坏手感。
起点 方向 结果 状态 说明
左半屏 → 右滑 拉出最近会话抽屉 你已定 抽屉在左，向右拉出。与顶栏 ☰ 按钮等价。
右半屏 ← 左滑 拉出总上下文洞察抽屉 你已定 抽屉在右，向左拉出。与顶栏 ◔ 按钮等价。
右半屏 → 右滑 候选 A / B / C 待拍板 往右滑，但右边没有可拉出的东西；左边的东西在这一半屏之外。
左半屏 ← 左滑 候选 A / B / C 待拍板 往左滑，与上一行完全对称。

A候选 A（推荐）：抽屉开着时反向滑 = 收起，没开时不响应

这两类手势恰好就是「把已经打开的抽屉推回去」的方向。会话抽屉开着时，左半屏往左滑正是推它回去；洞察抽屉开着时，右半屏往右滑同理 —— 两个方向都被赋予了自然含义，没有一个手势是白划的。

洞察抽屉开着 · 右半屏向右滑 → 收起抽屉
抽屉没开时会怎样：不响应，列表也不动。因为「往右滑」在右半屏不指向任何东西，不能让它去开左边的会话抽屉 —— 那等于回到 T076 的老问题（同一方向两个含义），用户划到中线附近时会左右横跳。

为什么这是推荐的：不需要用户记任何新东西。「往左推」推回左边的抽屉、「往右推」推回右边的抽屉，是这个手势本来就该有的意思。

无障碍：收起抽屉另有返回键与遮罩点击两条路径，手势只是加速，不承担唯一入口。
候选 B（全屏方向分派）：忽略半屏，右滑一律开会话、左滑一律开洞察。
好处是规则只剩一条、最好记；坏处是「在右半屏右滑」也会把左边的会话抽屉拉出来，手指方向和面板出现方向又变成逆的 —— 这恰好是现在被抱怨的那个问题，只是换了个抽屉。另外它让「半屏」这个概念彻底没用，等于没做分区。

候选 C（死区）：这两类手势完全不响应，抽屉也不动。
最保守，绝不误触；但用户划完会觉得「没反应 = 卡了」，而且抽屉开着时想收起来只能去点遮罩或返回键，手感上少了一条最自然的路。

3跟手过程：从哪一半起手，就从哪一边推出来

手指往哪边走，面板就从哪一边跟出来。左侧面板向右滑时左边先露出来，右侧面板向左滑时右边先露出来；拖到一半松手会回弹，划过 35% 就吸附到全开。两个方向各自独立，不会同时被拖动。

4可滑动标识：两侧各一条，首次进入淡出

分区规则本身是看不见的，所以首页要有可滑动标识。R050 定稿时只在右下角放了一条「右滑看总览」；现在有两个方向，标识也要成对，并且分别贴在自己那一半的底角 —— 用户看到左边那条就知道左边能滑，看到右边那条就知道右边能滑。

位置：两条标识各自贴在所在半屏的底角（左边那条距左缘 10dp、右边那条距右缘 10dp），都在列表内容之上。它们不侵入中线附近，所以不会互相挤在一起。

样式：沿用 R050 的胶囊（10dp 圆角、主色/绿色描边 + 12% 底、9.5sp 字、箭头在文字外侧指向滑动方向）。左用主色 #5AA2FF、右用运行绿 #4ADE80，与两个抽屉各自的强调色一致。

什么时候显示：只在用户还没用过该手势时显示，任一侧划过一次即永久消失（存本地，与 R049「看过即清」同一套语义）。两侧各自独立 —— 划过左边不影响右边那条。

为什么不做成常驻：常驻的提示最后会变成视觉噪声（列表每屏都在闪），而这两个手势一旦学会就再不需要提示。R050 定稿的「右滑看总览」当时也是这个判断。

无障碍：两条标识都是 clearAndSetSemantics {} 对读屏隐形，不制造额外的可聚焦节点；两个抽屉各自有顶栏按钮（☰ / ◔）作为不依赖手势的等价入口。
