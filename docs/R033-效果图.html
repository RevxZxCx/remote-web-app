⑤ 证据：为什么不做「删除」

以下是我在桌面端（F:\DSH\resources\app.asar）与远程 API 上逐条验证的结果，供你判断。

  • App 里出现的 session/* 方法名共 20 个（grep -o 去重实测）：attachment / canOpenWorkspacePath / cancel / control / create / follow / fork / initializeDefaultModel / list / modelCatalog / openWorkspacePath / page / projections / prompt / rename / search / selectModel / title / updateQueue / workspacePathApplications —— 没有 delete / remove / purge。
  • POST /remote/api/session/delete 试过三种参数形状（{sessionId} / {_request:{…}} / {}），全部 not found。
  • HTTP 侧 DELETE /api/sessions/<id> 返回 401 unauthorized（那是桌面端网页自己的鉴权，设备头走不通）。
  • asar 里确实有 16 处 session/delete，但全属 ACP 协议（agent 侧）的 schema，与 remote API 是两套东西。
  • 唯一可用的"移除"是 workspace/archiveSession（按工作区批量）与 workspace/pinSession。
所以三个候选里，按你选的 B 落地：
  • 采纳 不加「删除」；「归档」改称「移入归档」，加二次确认，文案明确"可从已归档找回"。
  • 待你定 抽屉底部「已归档」入口要不要真做？现在归档的会话在 App 里看不到，只能去桌面端取消归档。要做得新增一个归档视图（数据已有：session/list 带 archived 过滤）。
  • 待你定 搜索框要不要真接 session/search？
