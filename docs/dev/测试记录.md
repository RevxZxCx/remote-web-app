### ❌ 失败项 1：Gradle 8.8 无法配置 AGP 8.13.2 项目

**现象**：
```
Failed to apply plugin 'com.android.internal.application'.
> Failed to create service 'AndroidProblemReporterProvider_...'.
   > Unable to determine constructor argument #1: missing parameter of type InternalProblems
```

**原因**：本机 `C:\Users\26903\.gradle\wrapper\dists` 里 **只有 `gradle-8.8-bin` 是完整可用的**（`gradle-8.13-bin`、`gradle-8.5-bin` 都只有 `.part`/`.lck`，没有 `gradle.bat`）。AGP 8.13.2 要求 Gradle ≥ 8.13，用 8.8 跑 `gradle wrapper` 时**连项目配置阶段都过不去**。

**教训**：**不能在有 AGP 插件的项目根目录里跑 `gradle wrapper`**。正确做法是在一个空目录里用可用的旧 Gradle 生成 wrapper，再把 `gradlew` / `gradlew.bat` / `gradle/wrapper/*` 拷进项目。

**已验证的解法**：
```powershell
$g='C:\Users\26903\.gradle\wrapper\dists\gradle-8.8-bin\dl7vupf4psengwqhwktix4v1\gradle-8.8\bin\gradle.bat'
$t='F:\_wrapboot'; New-Item -ItemType Directory -Force -Path $t | Out-Null
Set-Content "$t\settings.gradle.kts" 'rootProject.name = "wrapboot"'
cd $t; & $g wrapper --gradle-version 8.13 --distribution-type bin
# 然后把 gradlew / gradlew.bat / gradle\wrapper\* 拷到项目根
```

### ❌ 失败项 2：最新 androidx / OkHttp 要求 AGP 9.1 + compileSdk 37（尚不存在）

**现象**（`assembleDebug` 直接失败，31 条同类错误）：
```
28. Dependency 'androidx.compose.ui:ui-android:1.12.1' requires Android Gradle plugin 9.1.0 or higher.
29. Dependency 'androidx.core:core-ktx:1.19.1' requires ... compile against version 37 or later of the Android APIs.
31. Dependency 'com.squareup.okhttp3:okhttp-android:5.5.0' requires ... version 37 or later.
```

**原因**：`maven-metadata.xml` 里的 `<release>`/最新版本是「已发布但面向下一版 SDK」的版本。直接取 latest 会踩到 **AGP 9.1 + compileSdk 37** 的要求，而这两个都还没正式可用（AGP 最高 8.13.2；SDK 平台最高 android-36）。

**教训**：**选版本必须读 AAR 里的 `META-INF/com/android/build/gradle/aar-metadata.properties`**，看 `minCompileSdk` 与 `minAndroidGradlePluginVersion`，不能看 `<release>`。

**实测出的兼容矩阵**（compileSdk 36 / AGP 8.13.2）：

| 依赖 | 可用上限 | minCompileSdk | 越界版本 |
| --- | --- | --- | --- |
| `androidx.compose.ui:ui-android` | **1.11.4** | 35 | 1.12.0+ → 37 / AGP 9.1 |
| `androidx.compose:compose-bom` | **2026.06.01**（ui 1.11.4） | — | 2026.08.00 → ui 1.12.0 |
| `androidx.core:core-ktx` | **1.18.0** | 36 | 1.19.1 → 37 / AGP 9.1 |
| `androidx.activity:activity-compose` | 1.13.0 | 36 | — |
| `androidx.lifecycle:lifecycle-runtime-ktx` | 2.11.0 | 34 | — |
| `androidx.lifecycle:lifecycle-viewmodel-compose` | **2.10.0** | 35 | 2.11.0 → 37 / AGP 9.1 |
| `com.squareup.okhttp3:okhttp-android` | **5.4.0** | 36 | 5.5.0 → 37 |
| `androidx.compose.material3:material3-android` | 1.4.0 | 35 | — |

**最终采用**（`gradle/libs.versions.toml`）：AGP 8.13.2 / Kotlin 2.2.21 / core-ktx 1.18.0 / lifecycle 2.10.0 / activity-compose 1.13.0 / compose-bom 2026.06.01 / okhttp 5.4.0 / serialization 1.9.0 / coroutines 1.10.2。

### ❌ 失败项 3：lint `PropertyEscape` 报错（error 级，会中断构建）

**现象**：
```
local.properties:2: Error: Windows file separators (\) and drive letter separators (':')
must be escaped (\\) in property files; use F\:\\Android\\Sdk [PropertyEscape]
```

**原因**：`sdk.dir=F:\\Android\\Sdk` 里**冒号没转义**。

**修复**：写成 `sdk.dir=F\:\\Android\\Sdk`。

**教训**：property 文件里 Windows 路径的**反斜杠和冒号都要转义**。另外 `lintDebug` 对 error 级问题会**直接中断构建**，所以 lint 必须进 CI 步骤。

1. `PropertyEscape`（error 级）→ `local.properties` 改为 `sdk.dir=F\:\\Android\\Sdk`。

**教训**：`lintDebug` 对 error 级问题**直接中断构建**。因此 `lintDebug` 必须作为每个阶段提交前的固定步骤（已写进 `开发流程.md` 第 1 节 ③ 自测）。
