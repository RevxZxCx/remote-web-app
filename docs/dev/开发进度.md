**本阶段**确定的接口契约（见 `测试记录.md` T016）：

| 端点 | 关键点 |
| --- | --- |
| `workspaceFiles/read` | `{workspaceFileScopeId, path, range}`，**`range` 必需**；`range.offset` **1-based**；`limit ≤ 5000`（服务端硬拒，客户端必须 coerce） |
| `workspaceFiles/readBytes` | **`options` 必需**；成功回 **multipart/form-data**（不是 JSON 信封），失败才回 JSON |
| `changes.summary` | `GET /remote/api/changes.summary?sessionId=&seq=` → `{turn,files,total,added,deleted}`；**`total` 是截断前完整数** |
| `changes.diff` | `GET ...?sessionId=&seq=&index=` → `{kind,path,display,before,after,hunks,coarse}`，**键名是 `before`/`after`** |
| — | 摘要**只存在 Host 内存**：Host 重启后旧轮次回 `text/plain` 的 404；`workspace/changes` 事件体**只有 `{turn}`**，须拿该事件 `seq` 去查 |

**关键实现点**：
1. `workspaceFileScopeId` 传的是 **sessionId**（服务端拿会话 `cwd` 推导根）；相对路径是相对**会话 cwd**，不是仓库根。
2. `workspaceFiles/read` 的 `version` 是**不透明字符串**（`2296164758:1688849842:539:...`），别解析成数字。
3. multipart 的 body **尾部还有一段 JSON 元数据**，part 内容必须按 boundary 切分，不能假设「到结尾」；**必须按字节切**（先转 String 会破坏 PNG/PDF）。
4. 桌面端 `MarkdownText` 的策略是「冻结除最后两块外的全部块、只重解析尾部」——`MdStream` 照抄，并把「`update(text)` 恒等于 `MdParser.parse(text)`」写成**单测断言的不变量**。
5. 高亮库的 `CodeHighlight` 区间**可能互相交叉**，直接逐个 `withStyle` 叠加会「后加的被先加的盖住」→ 必须先压成逐字符表再合并。
6. `MdFileRef.looksLikePath` **故意保守**（误判代价 > 漏判）：相对裸文件名不算，带目录的相对路径算。**R005 发现盘符分支曾是死代码**（冒号在否决字符集里且先于盘符判断），已修为「先剥盘符再校验剩余部分无冒号」。
7. 三条限制**必须写进 UI 文案**：Host 重启后旧轮次无改动卡片与 diff；非 git 仓库里纯 shell 命令改的文件看不到；单文件 > 2 MiB 不做 diff。降级路径 = 「从工具调用推断的文件行 + 当前全文」。

**本阶段**确定的接口契约（源码核实，见 `需求文档.md` §3.5）：

| 端点 | 模式 | args wire 名 | 形状 |
| --- | --- | --- | --- |
| `session/follow` | ⚡流 | `request` | `{address:{kind:'session',sessionId}, assistantStream?:true, maxMessages?, turnWindow?}` |
| `session/page` | unary | `request` | `{address, throughSeq, beforeSeq?, maxMessages?, turnWindow?}` → `{records:[{type:'event',event}], hasMore}` |
| `session/prompt` | unary | `request` | `{requestId, sessionId, mode:'queue'\|'steer', content, clientTimeZone?}` → `{accepted:true}` |
| `session/cancel` | unary | `request` | `{sessionId}` → `{accepted:true}` |

**`session/follow` 帧**（`typert.remote-client.js:221-424`）：
- `{type:'snapshot', header, cursor, records:[{type:'event',event}], hasMore, projections, assistantStream?}`
- `{type:'event', event}`
- `{type:'assistant-stream', frame}` —— `frame` = `{type:'start',attemptId,revision,startedAfterSeq,turn,step}` / `{type:'chunk',attemptId,revision,index,time,chunk}` / `{type:'end',attemptId,revision,index,outcome:{kind:'committed',eventType,seq}\|{kind:'abandoned'}}`

**事件信封**（`lib/types/client/session-wire-event.js:10-42`）：`{type, seq, time, data, ignorable?, surfaceOp?, sourceEventSeqs?}`——**键是封闭集合**，多一个键服务端就会抛。

**关键实现点**：
1. `AssistantStreamRecord` 是**压缩**表示（`text-chunks` 带 `time0`+`dt[]`+`texts[]`），不是逐条 delta。`expandAssistantStream` 才是展开逻辑（`client.js:1251-1291`）：`time = time0`，之后 `time += dt[index-1]`，逐条产出 `{type:'text-delta'|'reasoning-delta'|'tool-call-delta', index, ...}`。
2. `assistant-stream` 帧的 `chunk.chunk` 是 `StreamChunk` 联合（`{type:'text-delta',index,text}` / `{type:'reasoning-delta',index,text}` / `{type:'tool-call-delta',index,id,name?,argumentsDelta}` / `{type:'block-start'|'block-end'|'usage'|'finish'}`）。
3. 流式与持久化**会重复**：`assistant/message` 事件是权威结果，`assistant-stream` 是瞬时预览。桌面端 `ClientAssistantStream`（`lib/types/client/sessions/assistant-stream.js`）用 `pending` + `publishedSeqs` 去重，在 `end` 帧的 `outcome.kind==='committed'` 时发布对应 seq 的持久化条目。**M3 简化为**：流式增量只写进「当前活跃气泡」，一旦收到 `assistant/message` 事件就用持久化内容替换该气泡——不实现 revision/rebaseline 那套重连对齐（留 M4）。
4. `tool/call.arguments` 是 **JSON 字符串**，要自己 parse。
5. `address` 用 `{kind:'session', sessionId}`；子代理会话必须用 `{kind:'subagent', parentSessionId, childSessionId, mode}`，用错报 `session/agent-busy` 或 `subagent/unauthorized`。

## 已核实的接口契约（速查，详见需求文档 §3）

**传输**：Typert RPC，不是 REST。
- unary：`POST /remote/api/<namespace>/<method>`，头 `x-dsh-remote-device: <deviceId>`，体 `{type:"client-request", rpcId, method, payload}`，`payload = {args: {...}}`
- 流式：**一条** WebSocket `wss://<host>/remote/api/remote.mux?device=<deviceId>` 多路复用所有流
- 服务端信封：`{type:"server-response", rpcId, result:{ok:true, value}}` 或 `{ok:false, error:{code,message,details}}`

**配对**：
- `POST /api/pair/accept` `{token}` → `{ok:true, deviceId}`（走公网隧道也可，因为 public host 在 trusted 列表里）
- 二维码/链接只能在**桌面端**生成（`/api/pair/issue` 是 loopback-only）
- `GET /api/pair/status` → `{ok, paired, requirePairingForLan, publicUrl, lanAddresses, tunnel}`（免鉴权）

**参数 wire 名（真机确认，不是猜的）**：
- 多数方法：`{args: {request: {...}}}`
- **`session/list`：`{args: {_request: {...}}}`** ← 唯一带下划线前缀的
- `workspaceFiles/*`：`{args: {workspaceFileScopeId: <sessionId>, path, range|options}}`（第一个是 Typert lookup，传 sessionId）
- 流式端点无参数：`{args: {}}`
- 名字不对 → `gateway/arguments-invalid: args fields do not match the descriptor: missing "x"; unexpected "y"`

**时间字段**：线上是 ISO-8601 字符串（`"2026-10-12T21:25:11.055Z"`），类型声明写的是 `number`。两种都要能解析。

**App 实际会用到的 namespace**：`workspace`、`session`、`workspaceFiles`、`directoryPicker`、`skills`、`fileReferences`

**改动文件卡片**（非 Typert，是普通 HTTP 路由）：
- `GET /remote/api/changes.summary?sessionId=&seq=`
- `GET /remote/api/changes.diff?sessionId=&seq=&index=`
