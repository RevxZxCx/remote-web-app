## D01 · 交付形态：原生 Android App，直接对话 Typert RPC

**日期**：2026-10-13
**状态**：已接受（用户 m00002 提出目标，m00811 批准进入开发）

**背景**：现有 `@linxin666/dsh-remote-web-ui` 把官方桌面 SPA 搬到手机上，每次打开都要重新下载/加载插件、渲染整套 UI，用户原话（m00002）：

> 每一次重新打开网页都要加载一遍插件，相当于重启，加载时间非常的长，而且还需要渲染UI，整体交互性感觉很差

**决策**：不做 Web UI 的补丁，改为**原生 Android App**，直接实现 Typert RPC 客户端（unary HTTP + 一条 WebSocket mux），不加载任何官方前端资源。

**理由**：官方前端是桌面布局 + `mobile-adapt.ts` 事后注入 CSS 的适配层（`C:\Users\26903\.dsh\profiles\desktop\node_modules\@linxin666\dsh-remote-web-ui\src\client\mobile-adapt.ts`，约 1254 行），其中 `:143` 的规则

```
[class$="_frame"][data-sidebar-collapsed]{grid-template-columns:0 minmax(0,1fr) 0 !important}
```

把会话侧栏压成 0 宽，手机上根本没有会话选择器。原生 UI 一次性绕开「重载插件 + 渲染桌面 UI + 事后 CSS 补丁」三层成本。

**代价**：需要自己实现协议层、Markdown 渲染、diff 视图。

## D11 · 改动文件卡片：推断 + 权威摘要，两条路都做（Q10）

**日期**：2026-10-13 · **状态**：已接受（用户 m00811「接受建议」）

**决策**：
- **路 A（实时推断）**：解析 `tool/call` 的 `name ∈ {write, edit, str_replace_editor}` 与 `arguments`（**是 JSON 字符串**）取出 `file_path`，渲染可点文件行。
- **路 B（权威摘要）**：出现 `workspace/changes` 事件时，用其 `seq` 调 `GET /remote/api/changes.summary?sessionId=&seq=` 拿 `+added/-deleted` 权威统计。

**理由**：摘要只活在**同一 Host 进程内的会话**生命周期里，Host 重启后旧轮次返回 404；只做路 B 会空白。反之只做路 A 会丢行数统计。

**限制（必须写进 UI 文案）**：
1. Host 重启后旧轮次没有卡片与 diff（404）→ 降级为路 A。
2. 非 git 仓库里，纯 shell 命令改的文件不会出现在卡片里（只统计文件工具改动）。

## D12 · Markdown 渲染器：自绘（Q11）

**日期**：2026-10-13 · **状态**：已接受（用户 m00811「自绘」）

**决策**：自己实现 CommonMark + GFM 子集渲染器，**支持增量流式解析**。

**理由**：助手回复在协议层就是纯文本（`TextBlock = {type:'text', text}`），渲染完全是客户端决定。自绘可控性最好，尤其是「未闭合代码围栏在流式过程中也要正确显示」这一点，现成库的流式表现通常不达标。

**范围**：标题、段落、有序/无序列表、任务列表、引用、表格、围栏代码块、行内代码、粗体/斜体/删除线、链接、图片、分隔线。

## D17 · 传输层不依赖 `/remote` 之外的前缀

**日期**：2026-10-13 · **状态**：已接受（自主决策）

**决策**：所有业务请求统一走 `/remote/api/<namespace>/<method>`，WebSocket 走 `/remote/api/remote.mux?device=<id>`。

**理由**：插件 `/remote` 通道是唯一的**无 cookie** 入口，且它把请求以进程自身凭证重新签发到 `127.0.0.1`。直接打 `/api` 会被 harness 的 Host 围栏 + 浏览器 cookie 拦成 401（已实测：`POST /api/session.list` → `401 unauthorized`）。
