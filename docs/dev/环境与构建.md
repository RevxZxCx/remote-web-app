本机可用的完整 Gradle 分发只有 8.8（`gradle-8.13-bin`、`gradle-8.5-bin` 都只有 `.part`）。**不要在含 AGP 的项目根目录跑 `gradle wrapper`**，AGP 8.13.2 要求 Gradle ≥ 8.13，配置阶段就会失败。正确做法是空目录引导：

```powershell
$t='F:\_wrapboot'

# 再把 gradlew / gradlew.bat / gradle\wrapper\* 拷进项目根，然后删掉 $t
```

后续升级可直接用项目内的 `.\gradlew.bat wrapper --gradle-version <X>`（此时 wrapper 已是 8.13，能满足 AGP）。

### 6.1 无 LAN 时的真机联调：USB 端口反向映射

桌面端**只绑回环**（`GET /api/pair/lan-bind` → `bindHost: "127.0.0.1"`、`lanUrls: []`），
所以 `lanAvailable: false`、手机上无法直连桌面端 IP。用 adb 把端口反向映射过去：

```powershell
& $adb reverse tcp:19387 tcp:19387
```

之后手机上的 `http://127.0.0.1:19387` 即桌面端 DSH。配对链接可直接用
`http://127.0.0.1:19387/pair-accept?pair=<token>`（`127.x` 属私有地址，`HostPolicy` 放行明文）。

> 桌面端本机虽有一个 `192.168.0.106`，但服务没绑到它，所以局域网路径在当前配置下不可用。

### 6.2 用 adb 驱动 UI 的坑

1. **中文输入法会毁掉 `input text`**：搜狗/百度的拼音联想会把 URL 变成汉字
   （实测 `http://127.0.0.1:19387/pair-accept?pair=...` 被输成
   `http:、、、后天和他70。0。1: 19387、pair-啊猜测普通？`）。
   **解法**：临时 `& $adb shell ime disable <中文IME>`，输入完 **必须 `ime enable` 恢复**：
   ```powershell
   & $adb shell ime disable com.sohu.inputmethod.sogou/.SogouIME
   & $adb shell ime disable com.baidu.input_oppo/.ImeService
   # ... 输入 ...
   & $adb shell ime enable com.sohu.inputmethod.sogou/.SogouIME
   & $adb shell ime enable com.baidu.input_oppo/.ImeService
   & $adb shell ime set com.sohu.inputmethod.sogou/.SogouIME
   ```
2. **`screencap` 的图是 2× 下采样**（1080×2376 的截图 vs uiautomator 报告的坐标）。
   **点击坐标一律用 `uiautomator dump` 给出的 bounds**，不要照截图目测。
   `uiautomator dump` 的 XML 含未转义引号，PowerShell 的 `[xml]` 会解析失败；
   用 node 脚本按正则提取（`F:\bot\_uidump.js` 即此用途）。
3. **`adb shell "curl ..."` 在隧道 POST 上会挂住**，加 `--max-time`。

T008 记录的「隧道不可用」已修复。**App 侧代码一行未改**，修复全在桌面端部署环境，

**三层故障（必须逐层理解，缺一层都不通）**：

| 层 | 故障 | 修法 |
|---|---|---|
| 控制面 | DNS 给出的 `api.trycloudflare.com` anycast IP 对 `POST /tunnel` 稳定返回 **429**（code 1015），且限流会轮换 | `hosts` pin 到实测 200 的 IP（当前 `104.17.24.185`）。**会失效，需定期复查** |
| 数据面 | edge `TCP/7844` 按 ClientHello 的**明文 SNI** 做白名单：只放行 `region1/region2.v2.argotunnel.com`，拒绝整个 `*.cftunnel.com` 后缀——而 cloudflared 二进制里写死的 edge SNI 全是 `*.cftunnel.com` | ① `hosts` 把 `region*.v2.argotunnel.com` 钉到 `127.0.0.1`；② `tools\cloudflared-edge-relay.mjs` 在 `127.0.0.1:7844` 纯字节透传（经 Clash `CONNECT`）到真实 edge；③ **Clash `良心云` 组钉到 `🇭🇰香港高速03\|BGP\|CMCU`**（26 节点里唯一接受该 SNI 的） |
| 看门狗 | 插件 `TunnelManager` 每 60s 探测自己铸造的 quick tunnel URL，判活标准 `status < 500`；OS 把 `*.trycloudflare.com` 解析到**不可达**的 `104.16.230.132`/`104.16.231.132` → 探测必然超时 → 连 2 次失败即重启换 URL，**每次重启窗口公网返回 530** | `tools\tunnel-health-pin.mjs` 每 5s 把当前 live hostname pin 到可达 anycast IP |

**守护**：计划任务 `DSH Remote Tunnel Services`（登录时 + 每 5 分钟）跑
`tools\tunnel-services.ps1`，检查两个助手是否存活、7844 是否在监听，缺则重启。
**重启机器或助手崩溃后由它自动恢复**，无需手工介入。

**为什么不能走「给 cloudflared 配代理」**：实测它**不认** `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`；
`--proxy-*` 全部注明 *only takes effect if you define your origin with `--url`*（只管回源侧）。
**为什么不能改用具名隧道**：具名隧道同样用 `*.cftunnel.com` 的 edge SNI，换隧道类型解决不了 SNI 阻断。
**为什么不能在中继里改 SNI**：TLS 1.3 把整个 ClientHello（含 SNI 字节）纳入密钥派生，
改写必然导致 `decryption failed or bad record mac`。

这是**部署环境**问题，不是 App 缺陷。

### 手工探测接口（PowerShell 5.1 无 `-SkipHttpErrorCheck`，用 `HttpWebRequest`）

```powershell
function Probe($method,$url,$body){
  $r=[System.Net.HttpWebRequest]::Create($url); $r.Method=$method
  $r.ContentType='application/json'
  if($body){ $b=[Text.Encoding]::UTF8.GetBytes($body); $r.ContentLength=$b.Length
             $s=$r.GetRequestStream(); $s.Write($b,0,$b.Length); $s.Close() }
  try{ $resp=$r.GetResponse(); $sr=New-Object IO.StreamReader($resp.GetResponseStream())
       "$($resp.StatusCode) $($sr.ReadToEnd())" }
  catch [System.Net.WebException]{ $e=$_.Exception.Response
       if($e){ $sr=New-Object IO.StreamReader($e.GetResponseStream())
               "$([int]$e.StatusCode) $($sr.ReadToEnd())" } else { "ERR $($_.Exception.Message)" } }
}
Probe 'GET'  'http://127.0.0.1:19387/api/pair/status' $null
Probe 'POST' 'http://127.0.0.1:19387/api/session.list' '{}'
```

### 两个环境坑（都已修）

1. **首次必须联网**：`--offline` 解析不到 `ui-test-junit4` / `robolectric` / `concurrent-futures`。
   拉一次（`$env:HTTPS_PROXY="http://127.0.0.1:7897"`）落进 `F:\gradle-home` 后 `--offline` 可复现。
2. **JDK 模块封装**：
   `java.lang.RuntimeException: Failed to interact with raw FileDescriptor internals; perhaps JRE has changed?`
   根因 `IllegalAccessException: … cannot access class jdk.internal.access.SharedSecrets (in module java.base)`
   → `app/build.gradle.kts` 加
   `tasks.withType<Test>().configureEach { jvmArgs("--add-opens=java.base/jdk.internal.access=ALL-UNNAMED") }`。
   这是 JDK 模块封装，不是 Robolectric 的 bug。

### 写法要点（都是踩过的）

- **Robolectric 虚拟屏幕只有几屏高**：靠下的节点确实组合出来了、只是落在视口外，
  `assertIsDisplayed()` 会误报成「没画」→ 统一用 `assertExists()` / `assertDoesNotExist()`。
- **`performClick()` 落在视口外的节点上静默无效** → 用 `Modifier.height(240.dp).verticalScroll(...)`
  包一层再 `performScrollTo().performClick()`。
- **`Modifier.height(4000.dp)` 会收敛到父约束** → 要「给一个超高尚口」必须用 `requiredHeight(4000.dp)`。
- **`assertDoesNotExist` 是 `SemanticsNodeInteraction` 的成员函数，不是顶层扩展**，不能 import。
- 测试基建：`@RunWith(RobolectricTestRunner::class)` + `@Config(sdk = [36])` + `createComposeRule()`。
- 编译期弃用告警（未处理）：`createComposeRule()` 建议改
  `androidx.compose.ui.test.junit4.v2.createComposeRule`，但 v2 用 `StandardTestDispatcher`，
  会改变现有渲染测试的执行时机，需单独一轮迁移。
