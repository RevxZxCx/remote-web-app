已装插件 · 圆环七段 + 堆叠条 + 费用 + 耗时

插件格式的「上下文条」（照抄插件实现）

  • 高度 10px、圆角 5px、底色 neutral 18%，各段纯色紧贴、无间隙——与插件的 .lc-stacked 一致。
  • 剩余空间留白（不是画一条虚线），只有悬停某段时才给该段 brightness 1.18。
  • 下方刻度轴 13px：0 / 50% / 窗口上限。刻度用真实 token 数，不用百分比结尾——1M 窗口的人想知道「还剩多少 token」。
  • 七段顺序与圆环一致（按体量降序），不让用户在两个视图之间重新认颜色。
  • 这一段只在有 contextTimeline 时出现：核心的 contextBreakdown 只给三段粗粒度，画不出「哪些是助手输出、哪些是工具结果」。

费用

  • 来源 costUsage：{input, output, cacheRead, cacheWrite, reasoning, cost, byModel, byProviderModel}。
  • 合计用主色突出，四行明细用等宽字体，数字右对齐。
  • 按模型另起一张卡：byProviderModel 的键就是 provider:model，直接显示；费用为 0 的也照实显示（dfmodel 走的是自有额度，不是免费）。
  • 不显示货币符号以外的猜测：cost 是美元，直接 $ + 两位。

耗时 第二张圆环

  • 和累计构成用同一种图形：插件里它就是第二张圆环。同一个组件复用两次，用户不用学两套读法。
  • 五段来自 contextTimeline.timing：首字等待 ttftMs、推理 reasoningMs、正文生成 textMs（= 生成时长扣掉推理）、工具参数 toolArgMs、工具执行 toolsMs；五段之和 ≈ 墙钟，圆心直接显示墙钟。
  • 配色不复用累计构成那七种：这里是另一组量。首字等待蓝 / 推理紫 / 正文生成洋红 / 工具参数琥珀 / 工具执行青——与插件一致。
  • 圆心下方副标题写「墙钟」，选中后变「占比」；右侧 tok/s 徽标是解码速度，不占圆环。
  • 降级时（无 timing）只剩 sessionStats 的 llmMs / toolMs 两段，圆环退成两段，不是消失。
  • 「工具耗时 Top」是另一个维度（按工具拆），保留成单独一张卡，只列前 4 个。
  • 时长格式统一 Xh Ym（超过 1 小时）或 Xm Ys，不显示毫秒。
圆环与堆叠条是两个不同的量，必须分开：
圆环 = 全会话累计（3,869,342，跨 46 轮求和）；
堆叠条 = 当前窗口占用（156,634，本轮请求实际发出去的）。
两者差 24 倍，混在一起会让人以为上下文快爆了。

提示条的处理

  • 位置在占用卡与圆环之间——用户先看到「能看的」，紧接着看到「缺什么」，不会以为整个面板坏了。
  • 用 tertiary（琥珀）而不是 error：这不是故障，是「功能可以更全」。
  • 文案写明装了会多什么（七段 + 费用 + 工具耗时），而不是只说「请安装插件」。
  • 按钮不在 App 内跳转（手机上没有插件管理页），点击给 Snackbar：「请在桌面端的「插件」页安装 dsh-context」。
  • 装好插件后无需重新配对：session/projections 的键是动态的，下次打开抽屉就会多出来。这条也要写进文案，否则用户会去重配。
「核心自带」的判断依据：不看插件表里的 Config 列（那一列的说明是 Config marks packages whose row accepts a config mapping，说的是「这一行能不能带配置块」，与是否默认启用无关）。依据是默认 bundle 里有没有 - id: … 行：token-meter、session-stats、session-turn-outline 都有，属核心自带；contextTimeline、contextHeaders、contextActivity、costUsage 在核心 asar 里命中 0 次，只能来自插件。

6数据来源与降级判定

取数（一次读，之后走已在跑的流）

  • session/projections {request:{sessionId}} → values。打开抽屉时读一次；整包实测 ≈88 KB（25 个键，不支持只取指定键），所以不能轮询（3s 一次 = ≈30 KB/s）。
  • 之后靠 session/control 那条已经在跑的投影流：它每帧自带投影增量，零额外流量。关抽屉即停渲染订阅。
  • 文件走 workspaceFiles/list（扁平参数 {workspaceFileScopeId, path}，根路径用 .），按需拉取，不进上面的流。

判定逻辑（一行代码的事）

  • values["contextTimeline"] 存在 → 七段 + 堆叠条 + 详细耗时。
  • 否则 values["contextBreakdown"] 存在 → 三段 + 醒目提示。
  • 两者都没有 → 只显示占用进度条与tokenUsage，提示条文案换成「连基础统计都没返回，可能是桌面端版本过旧」。
  • costUsage 单独判：有就渲染费用卡，没有就整块不出现（不显示 $0.00 冒充）。
