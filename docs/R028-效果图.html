② 的另一半：会话抽屉的系统返回键（已复现 · 已定位）
你 m42278 澄清后我改对了目标：出问题的是首页左上角「三条横线」打开的那个最近会话抽屉，不是会话页。会话页本来就挂了 BackHandler（AppRoot.kt:334），抽屉一个都没有。
已复现（MuMu · Android 15 · 864×1920 · 已配对）：首页 → 点 cd="会话列表" 打开抽屉 → adb shell input keyevent 4 → topResumedActivity 变成 app.lawnchair/.LawnchairLauncher，Activity 被 finish、应用退回桌面（进程还活着）。
对照组：设置页按返回 → 回首页；会话页按返回 → 回首页。两处都不退出。也就是说手写的 BackHandler 全都有效，唯独抽屉这条路没人接。
已定位（更正了一版我先前的判断）——logcat | grep CoreBackPreview 显示抽屉打开后没有任何新的返回回调注册，按返回只有一行 Setting back callback null。反编译（javap）定位到具体一行：
① ModalNavigationDrawer 在 material3 1.4.0 里完全不注册返回回调（体内 PredictiveBackHandler 命中 0 次）——我先前写「它内部调了 handler、只是没到达平台」是错的；
② 注册只存在于接收 DrawerState 的新重载 ModalDrawerSheet(drawerState = …) 里（offset 738 无条件调 DrawerPredictiveBackHandler）；
③ 而 HomeScreen.kt:156 调的是不带 drawerState 的旧重载 ModalDrawerSheet { } —— 旧重载给内部参数传 aconst_null，随后被 ifnull 短路，注册路径根本没走。（HomeScreen.kt:122 的 drawerState 就在 HomeScreen$lambda$9 的参数表里、拿得到，只是调重载时没用上。）
修法（四种写法均已在设备上实测）：
ModalDrawerSheet(drawerState = drawerState) { SessionDrawer(…) } —— 推荐，一行改动，直接启用 material3 自带的预测性返回（上游设计意图），不新增 import、不自己写 BackHandler。
备选是显式接管 BackHandler(enabled = drawerState.isOpen) { scope.launch { drawerState.close() } }（放在 content lambda 内或 ModalNavigationDrawer 之前，两者实测同样有效）。三种不要叠加——双 handler 实测「后注册者优先」，叠加会让语义变晦涩。另加一条「抽屉打开时按返回只关抽屉、不 finish Activity」的回归测试，且要在你的 Android 16 真机上重跑（我全部实验在模拟器 Android 15 上做的）。

为什么不再给三个方案
之前那三个方案（两排 / 横滑 / 只留模型）全部是为「权限文字太宽」让路的。你指出权限只留图标就够——宽度问题当场消失，于是：
  • 不再需要横滑，也就不需要渐隐提示，手势冲突一并消失；
  • 不再需要把权限藏进「＋」的弹层，少一层点击；
  • 展开态比「两排」方案矮约 34dp，也就是你最初想要的那一排。
唯一的信息损失：当前权限级别默认不再直接可见，要点开图标才看得到。因为它是只读的，我按你的判断接受这个代价。

风格基线（两页共用的那套东西）

颜色：主色 #5AA2FF、背景 #0B1420、卡片底 #111C2B、描边 #22334A、次要文字 #A6BDD8；运行绿 #4ADE80、等待琥珀 #F2C14E、错误 #FF8A80。亮色主题一一对应（运行绿 #15803D）。
圆角：6 / 10 / 14 / 20 / 28，气泡 18，胶囊 999。
字号：标题 16/22、正文 14/21、脚注 11/15；数字与路径一律等宽。
动效：原地变化 140ms、进出 240ms、容器形变 360ms，缓动统一 cubic-bezier(.2,0,0,1)；每屏同时可见的无限动画不超过 2 个。
卡片：一律实底 + 1dp 描边（不再用半透明叠加）；会话/助手行用 2dp 左侧导轨代替底色。
