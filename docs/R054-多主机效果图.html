为什么「退出配对」要改叫「断开当前远程」
多主机之后，「退出配对」这个词只在一台主机时讲得通。有 3 台时它会被误解成「清空所有远程」。

新的语义分两层：
· 断开当前远程 = 只把当前这台从列表移除（等价于设备栏 ⋯ 里的「从列表移除」）
· 移除全部远程 = 真正的「清空」，放在设置页最底部，红色，带二次确认

原来「退出配对」的确认框文案也要跟着改，说清楚只影响这一台。

7可行性：要动哪些层

这不是纯 UI 改动。现在凭证只有一份、连接只有一个，多主机必须先改数据层。下面是已核实的现状与代价。
层现状要改成工作量
CredentialStore单份：load/save/clear，save 覆盖旧的列表 + 激活项：list/save/remove/setActive；文件格式要带版本号向后兼容中
AppContainer单条 connection按 id 懒建、缓存 N 条 DshConnection；切换时不重建旧的中
缓存分区已按 ownerId = SHA256(baseUrl\\0deviceId) 分区不用改，天然支持多主机—
ViewModel key已全部带 deviceId不用改—
UI顶栏标题固定标题入口 + 设备栏 + 三个对话框 + 设置页重排大
两个白捡的好处：① 缓存分区键早就带了 deviceId，各主机的消息本来就分开存，不需要迁移；② 所有 ViewModel 的 key 都带了 deviceId，切换时不会串数据。
一个真实代价：KeystoreCredentialStore 的文件格式目前是「2 字节头 + AES-GCM 密文」，改成列表要写迁移：读到旧格式时当成「只有一条」并立刻回写新格式，失败则保留旧文件不删。

8要你拍板的四件事

Q1 · 删除的措辞
设备栏里那台主机，用「从列表移除」还是「删除远程」？前者强调的是「本机不再显示」，后者容易被理解成「把桌面端那台机器也删了」。
从列表移除（推荐）删除远程
Q2 · 设置页的开关
现在「能力」那一段是只读文字（Markdown 渲染 / 代码高亮 / 长文件分页），代码注释里写明了理由：这些能力没有关闭的理由，做成开关等于让用户切进一个从没测过的组合。
但我在原型里画成了可点的开关（视觉上更完整）。要哪种？
保持只读（推荐 · 不变功能）真做成开关（要补实现与测试）
Q3 · 切换时如何处理原主机的连接
从「家里的主机」切到「公司服务器」时，前者的 WebSocket 是保持挂着（回来秒开，但白占内存与电量），还是断开（省资源，回来要重连约 1 秒）？
断开（推荐 · 同一时刻只连一台）保持（最多缓存 3 条）
Q4 · 未读圆点要不要跨主机汇总
上一轮刚做的未读圆点，现在是按当前主机的会话算的。多主机之后，别的主机上有会话跑完了，要不要在设备栏那一行也点亮一个圆点？
要（推荐 · 不然切过去才发现）不要（只看当前主机）
我的建议按这个顺序做：先落地数据层（凭证列表 + 容器多连接），这一步不改任何界面、可单独验证； 再做首页标题与设备栏；最后才是溢出菜单与设置页的重构——那两个是纯视觉，风险最低，放最后即使来不及也不影响主体功能。
