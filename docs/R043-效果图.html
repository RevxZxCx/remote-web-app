3解析映射表（服务端给什么 → 界面显示什么）

左侧是 turn/end 事件 data.reason 的原始形状（全部实测自本机 130 个会话、645 次轮次结束）； 右侧是 App 要呈现的样子。已经给出 error.message 的，必须原样展示——转述会把 「额度已用完」「没有 API key」这类可直接行动的信息揉成一句「出错了」。
reason.kind真实次数卡片主按钮
error~48本轮失败（红）
按 error.code 细分标题		按 code 决定：可重试给「重试本轮」，凭证/额度类不给
max-tokens33输出被截断（琥珀）继续写
aborted · user73本轮已中止（中性）继续
aborted · parent / disposed3本轮已中止（中性）
不写「你按了停止」		—
blocked7等待批准 / 被阻止（琥珀）去处理
interrupted5输出流中断（红）重新生成
completed465保持现状「第 N 轮结束」（灰细线）—
error.code标题文案是否给「重试」
RATE_LIMIT模型限流给（附「1 次重试后仍失败」）
QUOTA_EXCEEDED额度已用完不给，改「去桌面端查看」
MISSING_CREDENTIAL未登录 / 无密钥不给，原文明说去哪配
INVALID_REQUEST请求被拒绝给，但提示「换模型试试」

其他本轮失败给（保守：未知错误先允许重试）

7要动的地方（给开发看的）

两处改动都不触碰协议层——服务端早就把数据给全了。
#文件改什么
1core/session/SessionEventParser.ktturnEndNotice()：reason 从 stringOrNull 改成读对象，解析出 kind / error.message / error.code / reason.reason.kind
2core/session/ChatModel.ktChatItem.Notice 升级为 ChatItem.TurnResult（带 kind / code / message / 时长 / 是否有产出），旧 Notice 保留给标题类事件
3ui/chat/TurnResultCard.kt新文件：七种 reason.kind → 三种视觉（fail / cut / stop）；completed 不出卡片+ 展开收起 + 复制
4ui/chat/ChatScreen.kt渲染分支接新卡；「重试本轮」走已有 retrySend()；「压缩后重试」走 /compact 或提示
5ui/chat/ComposerAddSheet.kt新文件：三段式面板（添加 / 快捷 / 命令）
6core/protocol/DshEndpoints.kt新增 COMMANDS_LIST = "commands/list"（实测参数 {agentId}）
7core/command/CommandCatalog.kt新文件：拉 commands/list、按 name 排序、缓存一次；失败静默降级为「只有添加类」
8core/protocol/DshEndpoints.kt新增 FILE_REFERENCES_LIST = "fileReferences/list"（实测参数 {agentId, query}，返回 {path, kind:directory|file}）
已实测的协议形状（可直接用）
commands/list → {agentId}
返回 [{name, description, input?:{hint}, definitionId?}]
fileReferences/list → {agentId, query}
返回 [{path, kind:"directory"|"file"}]
turn/end → {turn, reason:{kind, error?{message,code}, reason?{kind}}}
降级策略：commands/list 拉不到（老版本桌面端 / 掉线）时，面板只留「添加」段并显示一行 「命令列表暂不可用」——不能把整个加号按钮禁掉，否则用户连图片都加不了。
