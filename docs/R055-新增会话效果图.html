6接口实测结果（这一轮已经跑过真机 curl）

结论全部来自对本机桌面端 http://127.0.0.1:19387 的真实请求，用合法 device id 打 /remote/api/{namespace}/{method}、头 x-dsh-remote-device。 用错外壳会直接得 gateway/bad-request: invalid client-request message。
端点真实 wire 形状结论
session/create args = {request:{...}} 可用。workspaceId / cwd / title / agentPreset / model 全部可选——只给 {request:{}} 也能建成功，返回 {sessionId, agentPreset}。 乱给 workspaceId 报 workspace/not-found；cwd:"" 报 gateway/internal（mkdir ''），所以空串不能传，要么不传要么传真路径。
agentPreset 取值 standard / ptc / minimal / cordis 服务端报错会把 available 数组整个吐出来，四档实测确认。中文名逐字取自桌面端 locale： 标准模式 / PTC 模式 / 极简模式 / 创造模式。compact、detailed、verbose 不是预设（那是渲染档位，别混）。
workspace/create args = {request:{path, title}} 可用但受限：path 必填且目录必须已存在，否则 workspace/invalid-path（ENOENT realpath）。 只给 title 报 gateway/input-invalid。返回 {workspace:{workspaceId,path,...}, created}。
directoryPicker/list 参数是裸 path（不是 request） 实测不可用：directory-picker/unavailable — directoryPicker.list needs the browse capability; the composed picker serves "native"。 → 「新建工作区」没法让用户在手机上选目录，见第 7 节 Q2。
workspace/follow 流，无参数（mode:'stream'） 工作区列表的唯一来源，App 里 WorkspaceRepository 已经接好了。注意：session/list 的条目没有 workspaceId 字段，别指望从那边反查。
踩过的坑：session/list 的 args 是 {"_request":{}}（下划线），而 session/modelCatalog 恰恰不能带 _request； 两者形状相反，抄错会得到 missing "_request" 或 unexpected "_request"。

8要你拍板的三件事

Q1 · 「新建工作区」要不要做
桌面端的目录浏览接口 directoryPicker/list 实测不可用（返回 directory-picker/unavailable，因为桌面端装的是 native picker）。 但 workspace/create 本身是通的——只要有一个已存在的绝对路径就能建。
所以要么让用户手填路径（长、易错、移动端打字痛苦），要么这一轮先不做。
先不做，菜单里显示禁用项 + 说明（推荐 · 你原话「没有接口即可选」） 做：弹一个手填路径的输入框（复用编辑地址那个对话框）
Q2 · 发第一条消息时才建会话，还是进页面就建
进页面就建：会话立刻出现在桌面端列表里；但用户按返回就是一条空会话垃圾（桌面端会留着）。
发送时建：不产生垃圾；代价是首次发送要多等一次往返（实测 session/create 约 100ms，可接受）。
发送时建（推荐 · 不产生空会话） 进页面就建（首次发送更快，但返回会留下空会话）
Q3 · 模式选择要不要记住上次的选择
现在桌面端有「新任务默认」的概念。App 这边每开一次新增会话都回到「标准模式」，还是要记住用户上一次选的那档？
记住要落一处本地偏好（还要考虑按主机分开记——A 机器上常用极简、B 机器上常用创造是可能的）。
记住，但只按主机记（推荐 · 少一次点击） 每次都回到标准模式（最简单，零状态） 全局记一个（不分主机）
建议的落地顺序：① 先只做 FAB + 跳转到一个「直接 = 对话页」的新页面（不带任何选择栏），把 session/create 打通并在真机上验证——这一步就能用；② 再加工作区胶囊（数据从已有的 workspace/follow 拿，零新接口）；③ 最后加模式胶囊与「记住上次选择」。
这样每一步都是可单独验收的，任一步出问题都不会把「新建会话」整条路堵死。
